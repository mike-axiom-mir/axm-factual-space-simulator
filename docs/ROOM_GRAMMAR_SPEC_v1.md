# Room Grammar Specification v1

## Layer model

### Universal bridge experience contract

Applies to every primary playable vessel. It protects spatial presence, visible participants, a dominant world view, and diegetic controls.

### Bridge archetype

Defines one vessel room: geometry family, station anchors, command arrangement, camera anchors, and minimum low-fidelity representation.

### Timeline start

Defines when and under which factual, simulated, or theoretical assumptions an expedition begins.

### Crew start

Defines occupants, roles, command positions, and visible station mapping.

### Render profile

Defines presentation quality only. A renderer does not own room semantics.

## First bridge grammar

The Frontier Survey Bridge uses a wide forward command deck.

- Front: dominant world screen.
- Center: shared command duet.
- Left: navigation and science.
- Right: engineering and communications.
- Rear: visible room depth, access, and auxiliary functions.
- Default camera: rear-center wide, showing room, crew, command, and universe together.

## Station focus

A close station view may enlarge a console, but some bridge context must remain visible or immediately recoverable. The station may not become a disconnected website page.

## Empty or alternate occupants

A seat can represent:

- a human;
- an AI;
- another machine;
- a remote collaborator;
- an autonomous role;
- an absent or currently unoccupied seat.

The spatial anchor remains. Different starts may define different command arrangements through new crew and bridge registrations.

## Future additions

A carrier, probe vessel, biological vessel, rotating habitat, lander, archive ship, or nonhuman command environment can use a completely different room grammar. It must still satisfy the universal lived-in-vessel contract unless explicitly classified as a non-vessel experience mode.
